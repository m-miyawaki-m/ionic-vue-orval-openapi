# 結果の確認・レポート保存先

各テスト層の結果がどこに残り、どう確認するかの一覧。レポートのリッチさはランナーで異なる。

## 保存先と確認方法

| 層 | コマンド | 結果の保存先 | 確認方法 |
|---|---|---|---|
| L1 Unit | `npm run test:unit` | **ファイル** `frontend/vitest-results/unit-junit.xml` + `unit-results.json`（＋ターミナル） | ファイルを開く／CI・P5で取込（各テスト名は `-- --reporter=verbose`） |
| L2 Component 挙動（Playwright CT） | `npm run test:ct` | **HTMLレポート** `frontend/playwright-ct-report/` | `npx playwright show-report playwright-ct-report` |
| L2 Component 挙動（Vitest browser） | `npm run test:browser` | **ファイル** `frontend/vitest-results/browser-junit.xml` + `browser-results.json` | ファイルを開く／CI・P5で取込 |
| L3 Visual（ビジュアル回帰） | `npm run test:visual` | **HTMLレポート** `frontend/playwright-report/`<br />基準画像 `frontend/tests/visual/visual.spec.ts-snapshots/*.png`<br />失敗時の実際/差分 `frontend/test-results/` | `npx playwright show-report` → http://localhost:9323 |
| L4 Functional/Application（E2E） | `npm run test:e2e` | **HTMLレポート** `frontend/playwright-report/` | `npx playwright show-report` → http://localhost:9323 |
| L5 Release Candidate（Android） | `npm run test:android:maestro` / `:appium` | 手動・スクショ（環境依存） | `frontend/android-tests/` の手順、実機エビデンス（スクショ） |

## Playwright HTMLレポートの開き方

e2e と visual は `playwright.config.ts` の `reporter: [['html', …]]` により HTML レポートを生成する。

```bash
cd frontend
npm run test:e2e        # または test:visual（playwright-report/ を生成・上書き）
npx playwright show-report   # http://localhost:9323 をブラウザで開く
```

各テストの成否・所要時間・ステップ・スクリーンショット、失敗時はトレースと**ビジュアル差分（actual / expected / diff）**を確認できる。

## 注意

- すべての出力先（`playwright-report/`・`test-results/`・`vitest-results/`・`playwright-ct-report/`）は **gitignore**（ローカル成果物・コミットしない）。**いずれも Storybook 非依存**で、`npm run test:*` を叩くだけで生成される。
- **Vitest と Playwright で出力先を分けている**: Playwright は `test-results/` を実行ごとに**クリーン**するため、Vitest(unit/browser) の JUnit/JSON は別ディレクトリ `vitest-results/` に出す（同居させると消える）。
- Playwright の HTMLレポートは実行のたびに**上書き**（e2e/visual は `playwright-report/`、CT は `playwright-ct-report/`）。素の `npm run test:e2e`/`test:visual`/`test:ct` で生成され、`--reporter=list` 等で上書き実行すると HTML は出ない。
- **Visual の基準画像は git 管理**（`tests/visual/visual.spec.ts-snapshots/`）で **OS/レンダラ依存**。別環境では再生成が必要。
- さらにインタラクティブな HTML ダッシュボードが欲しい場合は `@vitest/ui`（devDep）を追加して `vitest --ui`。

## 将来: 統合エビデンス（P5）

P5 の Python ツール（`tools/spec-evidence`, openpyxl）が `tests/cases/*.cases.json` と各テスト結果（JSON/JUnit）を結合し、**テスト仕様書＋エビデンス Excel**（1行=1テスト項目＋実測 pass/fail＋スクショ貼付欄）を出力する計画。これが「人が結果を一覧で確認する」最終成果物になる。
